EPL Pricing Intelligence

Complete System Design & Data Science Implementation Handbook | Version 1.0.0

1. EXECUTIVE SUMMARY

The EPL Pricing Intelligence System is a full-stack data science solution designed to optimize ticket revenue for English Premier League clubs while maintaining stadium atmosphere and regulatory compliance. It moves beyond static tiering into High-Fidelity Dynamic Pricing.

This handbook documents the three core intelligence layers:

  • Emotional Intelligence: The Stakes Engine quantify match importance.
  • Empirical Intelligence: The Conjoint Engine derive true Willingness-To-Pay (WTP).
  • Optimization Intelligence: The LP Optimizer solves for maximum yield under atmospheric constraints.

2. DOMAIN CONTEXT (THE EPL PRIMER)

For technical implementation purposes, the environment is governed by these rules:

  • Season Structure: 38 Matchweeks (MW). 20 Clubs. 380 total matches.
  • The 3-1-0 Rule: Win = 3pts, Draw = 1pt, Loss = 0pts. This drives the match_stakes_score.
  • The Away End Rule: Clubs MUST allocate 10% of capacity or 3,000 seats (whichever is lower) to visiting fans, capped at £30. This is a non-dynamic constant in the solver.
  • Club Tiers: Categorized into Big Six (Global brands), Established Mid (Stable demand), and Smaller Clubs (High volatility).

4. DATA SCHEMA & LINEAGE

The system relies on three primary data artifacts generated or consumed during the operational lifecycle.

Artifact 1: epl_match_data.json

The master registry of all 760 historical matches used for Layer 2 training. Contains booking_curve (61-day sales vectors) and inventory snapshots.

Artifact 2: epl_wtp_{tier}.json

Output of the Conjoint Engine. Stores zone_price_bounds (P10/P50/P90) which act as hard constraints for the LP Optimizer.

5. STAKES ENGINE (EMOTIONAL CALCULUS)

The Stakes Engine (stakes_engine.py) converts the current league table into a commercial multiplier.

5.1 The Urgency Multiplier

Matches in May are commercially more sensitive than matches in August. We apply a linear urgency decay:

U(MW) = 0.1 + (MW - 1) * (0.9 / 37)

5.2 Title Race Intensity

For two clubs in the top positions:

Score_{title} = (1 - \frac{Gap_{Home} + Gap_{Away}}{2 \times Points_{Remaining}}) \times U(MW)

Selection Logic: The Dominant Narrative

A match can be both a "Top Four Battle" and a "Derby." The system calculates all possible scores (Title, Top 4, Relegation, Euro) and uses max() to select the highest signal as the match_stakes_score.

6. CONJOINT ENGINE (HB-MNL MODELING)

Located in conjoint_engine_epl.py, this engine solves the "Willingness-to-Pay" problem using Bayesian inference.

6.1 Hierarchical Bayesian Multinomial Logit

We assume every fan $i$ has a utility $U$ for a ticket option $j$:

U_{ij} = \beta_{i, price} \times Price_j + \sum \beta_{i, k} \times Attribute_{jk} + \epsilon_{ij}

6.2 Price Sensitivity Prior

Because price is a disutility, we force the price coefficient to be negative using a Log-Normal or Exponential prior in PyMC:

mu_price = pm.Normal("mu_price", -3.0, 1.0) beta_price = -pm.math.exp(mu_price + price_offset * sigma)

6.3 Output: WTP Boundaries

The engine computes the Equivalent Price Premium for each zone. For example, the premium for "Hospitality" relative to the base "Away End" (£30) is:

WTP_{premium} = \frac{U_{hospitality} - U_{away}}{|\beta_{price}|}

8. FORECASTING ENSEMBLE (LAYERED)

The forecasting engine (forecasting_engine_epl.py) uses a 4-layer stack to predict the overall_fill_rate.

8.1 Layer 1: Time-Series Decomposition

  • STL: Period=19 (home games). Identifies if a club is currently "Trending" (e.g., Aston Villa's rise).
  • DTW Clustering: Assigns the match to one of 5 Booking Curve Archetypes (e.g., "Late Surge" for relegation battles).

8.2 Layer 2: LightGBM Tabular Learner

A gradient boosting model trained on 25+ features. It is the final arbitrator of demand.

Training Constraint: The Sellout Ceiling

Because most Big Six matches sell out (Fill Rate = 1.0), the model is trained on Excess Demand Ratio (where 1.15 means demand is 15% above capacity) to allow the Optimizer to push prices even when attendance is maxed out.

9. LP OPTIMIZER (REVENUE YIELD)

The EPLLPOptimizer uses Mixed-Integer Linear Programming (MILP) to find the optimal price vector $P^*$.

9.1 Objective Function

Maximize \sum_{z \in Zones} \sum_{k \in Prices} x_{zk} \times Price_{zk} \times Quantity_{zk}

9.2 The Attendance Floor

For non-Big Six clubs, atmosphere is protected via a 65% attendance floor constraint:

\sum_{z} Quantity_{z} \ge 0.65 \times Capacity_{total}

9.3 Monotonicity Constraint

To prevent "Price Inversion" (where a worse seat is more expensive than a better one):

prob += p_hospitality >= p_lower_tier
prob += p_lower_tier >= p_upper_tier
prob += p_upper_tier >= p_general_sale

10. LIVE SIGNAL PIPELINE

This is the most critical operational component. It corrects the forecast in real-time.

Velocity Deviation ($\delta$)

If tickets sold at T-14 exceed the medoid of the assigned Archetype:

\delta = \frac{Sold_{Actual}}{Sold_{Medoid}}

If $\delta > 1.2$, a Price Surge is triggered automatically.

11. INTEGRATION & API LAYER

The system is exposed via FastAPI on Port 8001.

12. GOVERNANCE & PERFORMANCE

Model performance is tracked via MAPE (Mean Absolute Percentage Error). In production, an alert is triggered if MAPE exceeds 15% over a 5-match rolling window.

13. ROADMAP & KNOWN GAPS

  • Gap: Secondary Market API. Currently using synthetic resale values. Integration with StubHub/Viagogo API is required for "Resale Parity" pricing.
  • Gap: Dynamic Hospitality. Only 20% of hospitality is currently dynamic; the rest is fixed contract.
  • Future: Player Transfer Impact. Integration of "Transfer Rumor Sentiment" as a leading demand indicator.
