Deep Technical Playbook

Mathematical foundations and algorithmic intuition for the EPL (English Premier League) Pricing Intelligence System.

0. DOMAIN PRIMER: FOOTBALL CONCEPTS

This system operates within the rules of the English Premier League. For the purpose of technical validation, the following sports concepts are defined as follows:

  • The Points System: In every match, a team earns 3 points for a win, 1 point for a draw (tie), and 0 points for a loss. These points determine the team's rank in the League Table.
  • Matchweek (MW): The season is divided into 38 rounds of matches. Each round is one Matchweek. The system uses the Matchweek index to calculate "Season Urgency."
  • Home vs. Away: The Home team hosts the match at their stadium. The Away team travels to the opponent's venue. This distinction is critical as Home teams generally have higher demand.
  • Goal Difference (GD): If teams have the same number of points, the one with the higher Goal Difference (Total Goals Scored minus Total Goals Conceded) is ranked higher.
  • The League Table: A live ranking of all 20 clubs. The top 4 clubs qualify for the "Champions League" (High Revenue), while the bottom 3 clubs are "Relegated" (moved to a lower division), which is a financial disaster.
  • Derby: A match between two clubs located in the same geographic city (e.g., Arsenal vs. Tottenham). These matches have naturally higher emotional demand.

1. STAKES ENGINE (Emotional Intelligence)

LOCATION: EPL/stakes_engine.py CADENCE: 2-HOURLY

The Stakes Engine is a Contextual Normalization Layer. It converts ordinal league table positions and point gaps into a continuous probability-like score [0,1] that scales price elasticity.

1.1 The Urgency Decay Function

Equation 1.1 U(t) = 0.1 + (MWt - 1) × (0.9 / 37)
Intuition: Stakes are not static. A "Title Decider" in Matchweek (MW) 10 is less important than one in Matchweek 38 because the "Points Available" (Sunk Cost) has decreased. This linear ramp ensures that importance grows as the "Finality" of the season increases.

1.2 The Narrative Closeness Score

For Title and Relegation races, we use a Symmetric Point-Gap Normalization:

Equation 1.2 Scloseness = 1 - [ (GapHome + GapAway) / (2 × MaxPointsRem + 1) ]
Intuition: If both teams are 1 point away from the leader in MW38, the Gap is small, making Scloseness near 1.0. If they are 15 points away with 2 games left, the score drops to near 0.

1.3 Maximum Narrative Selection

raw_score = max(title_score, top4_score, relg_score, euro_score) final_score = clip(raw_score * urgency, 0, 1)

Logic: We take the max() because a match's commercial value is defined by its primary storyline. Adding them would create "Super-Stakes" artifacts (e.g., scores > 1.0) which break the downstream Forecasting regression.

2. FORECASTING ENGINE (Demand Prediction)

LOCATION: EPL/forecasting_engine_epl.py CADENCE: WEEKLY (RE-TRAIN)

A Stacked Regressor that decomposes club momentum and fixture-specific shocks using **LightGBM (Light Gradient Boosting Machine)**.

2.1 STL Decomposition

Equation 2.1 Yt = Tt + St + Rt
Intuition: We use **STL (Seasonal-Trend decomposition using Loess)**.
Tt (Trend): Captures the club's "Season Form" (e.g., Unbeaten run).
St (Seasonal): Captures the "Fixture Periodicity" (e.g., High demand in Festive/December fixtures).
Rt (Residual): What the LightGBM model attempts to learn (External shocks like injuries or weather).

2.2 The Velocity Integration

Velocity (V) is the derivative of the Booking Curve. The model ingests two live signals:

VT-x = (AttendanceT-x - AttendanceT-(x+1)) / Capacity

Logic: If VT-14 deviates from the **Archetype Medoid** (calculated via **DTW (Dynamic Time Warping)** in the engine), the model shifts the forecast toward a "Low Demand" cluster, triggering an automatic price reduction in the Optimizer.

3. LP OPTIMIZER (Revenue Maximization)

LOCATION: EPL/lp_optimizer_epl.py CADENCE: T-45 DAYS

Translates probability into price using a MILP (Mixed-Integer Linear Program) solver.

3.1 The Linearized Demand Curve

Equation 3.1 Q(P) = Qbase × [ 1 + ε × (P - Pmedian) / Pmedian ]
Intuition: Since demand is not static, we assume a linear slope around the **WTP (Willingness-to-Pay)** median price derived from conjoint analysis. ε (Elasticity) determines the "steepness." For **Hospitality (ε = -0.10)**, the slope is flat—raising prices has almost no effect on quantity. For **General Sale (ε = -1.10)**, the slope is steep—a 10% price hike kills demand by 11%.

3.2 The Revenue Objective

Maximize Z = Σz (Pz × Qz)

Subject to:

  • Phosp ≥ Plower ≥ Pupper ≥ Pgen (Monotonicity Constraint)
  • Σ Qz ≥ 0.65 × Σ Capz (Atmosphere Protection/Attendance Floor)

4. CONJOINT ENGINE (WTP Discovery)

LOCATION: EPL/conjoint_engine_epl.py CADENCE: SEASONALLY

The "Source of Truth" for Willingness-to-Pay (WTP). It uses HB-MNL (Hierarchical Bayesian Multinomial Logit).

4.1 The MNL Probability Function

Equation 4.1 P(i) = exp(Vi) / [ exp(Vi) + exp(Vj) ]
Intuition: A fan chooses Option A over Option B if its Utility (V) is higher.
V = β0 + βprice×Price + βopp×Opponent + ...
The **βprice** is the "Coefficient of Pain." The larger it is, the more sensitive the fan is to cost.

4.2 Hierarchical Bayesian (HB) Sampling

Instead of one β for the whole league, we estimate a unique βi for every respondent using the **NUTS (No-U-Turn Sampler)**:

βi ~ Normal(μ, Σ)

Logic: This allows us to capture **Heterogeneity**. We learn that "Tourist" fans have a low βprice (price insensitive) while "Local" fans have a high βprice (price sensitive). The Optimizer uses the **P50 (50th Percentile / Median)** of this distribution to set the standard price ceiling.
